# План усиления `engines/s.py`

Ниже — приоритетный roadmap, чтобы поднять силу в bullet/blitz/rapid без полной переписки движка.

## 1) Быстрый прирост Elo (1–3 дня)

1. **Убрать дорогие вычисления из `eval_board()`**:
   - `files_bb` пересчитывается на каждом вызове оценки;
   - для каждого пешечного `sq` строятся списки `ahead_sqs`.
   
   Это стоит вынести в предвычисленные таблицы (`FILE_MASKS`, `PASSED_PAWN_MASK[color][sq]`) на старте.

2. **Улучшить time management**:
   - сейчас бюджет хода берётся как грубая формула с `movestogo=30` по умолчанию;
   - добавить panic-time (если `score` резко падает на итерации), защиту от флага и чуть агрессивнее использовать инкремент в bullet.

3. **Сделать quiescence чуть “умнее”**:
   - добавить `delta pruning`;
   - в qsearch смотреть не только взятия, но и шахи в 1–2 полухода (ограниченно).

## 2) Средний объём работ, хороший ROI (3–10 дней)

1. **PVS (Principal Variation Search)** вместо полного окна для всех ходов.
2. **Killer moves + counter-move history** вместе с уже имеющимся history heuristic.
3. **Aspiration windows по последнему score** уже есть базово, но сделать адаптивными по глубине/волатильности.
4. **Static Exchange Evaluation (SEE)** для фильтрации/сортировки “ядовитых” взятий (лучше текущего SEE-lite).

## 3) Усиление оценки позиции (важно для rapid)

1. Добавить:
   - изолированные/сдвоенные/отсталые пешки;
   - mobility (особенно для лёгких фигур);
   - rook on open/semi-open file;
   - king shelter (пешечный щит вокруг короля) вместо только open-file/center штрафов.
2. Усложнить passed pawns:
   - учитывание защищённости проходной;
   - бонус по продвижению и blocked/unblocked статусу.

## 4) Архитектурные шаги для Python-движка

1. **Инкрементальная оценка** (обновлять score при `make_move/undo_move`, а не считать почти всё с нуля).
2. **Инкрементальные attack maps/pin info** для уменьшения повторных `is_square_attacked/get_attackers`.
3. Локальная микрооптимизация hot-path:
   - локальные переменные в циклах;
   - минимизация выделений списков/объектов;
   - профилирование (`cProfile`, `py-spy`) и оптимизация top-5 узких мест.

## 5) Тестирование и измерение (обязательно)

1. **SPRT**/A-B тесты на фиксированном наборе тайм-контролей:
   - bullet 2+1;
   - blitz 5+3;
   - rapid 10+5.
2. Раздельные прогоны:
   - self-play (старый vs новый);
   - gauntlet против внешних UCI-движков одинаковой силы.
3. Логировать: nps, глубину, fail-high/fail-low частоту, % времени на ход.

## Рекомендуемый порядок внедрения

1. Предвычисленные маски + оптимизация eval hot-path.
2. Time management (panic-time + anti-flag).
3. PVS + killer/counter history.
4. SEE + улучшенный qsearch.
5. Расширение eval (mobility/structure/shelter).
